# v0.4 Implementation Backlog

This backlog is subordinate to ADR-003 and `V0.4_SYSTEMATIZATION_EXPERIMENT.md`.

The order is deliberate: measurement infrastructure before transformer sophistication.

## P0 — Experiment foundation

### P0.1 Draft contract

- [x] Define provider-independent draft format.
- [x] Distinguish `extracted`, `inferred`, and `user_authored`.
- [x] Define evidence references and human review decisions.
- [x] Define compile invariants.

**DoD:** contract is versioned and an evaluator can reject structurally invalid drafts.

### P0.2 Evaluation rubric

- [x] Define deterministic validity metrics.
- [x] Define topic/relation recall.
- [x] Define provenance and origin-label metrics.
- [x] Define correction/TTSU measurement.
- [x] Explicitly avoid one opaque aggregate score.

**DoD:** each success criterion maps to a measurable field or explicit human verdict.

### P0.3 Benchmark #001

- [x] Freeze a representative real research corpus.
- [x] Define minimum expected structure and case thresholds.
- [x] Create human-curated gold draft fixture.
- [x] Document known ambiguities and baseline fields.

**DoD:** deterministic evaluator passes the gold fixture and does not require AI/network access.

## P1 — Deterministic pipeline skeleton

- [ ] Add `SourceAdapter` interface for raw Markdown/conversation exports.
- [ ] Normalize input into stable source fragments.
- [ ] Add draft contract validator as reusable module rather than CLI-only logic.
- [ ] Add `PackCompiler` that compiles reviewed node/edge proposals to Knowledge Pack v1.0.
- [ ] Reject unresolved conflicts, dangling edges, cycles, duplicate IDs.
- [ ] Preserve provenance sidecar data through the review session.

**DoD:** a hand-authored draft can travel source → validate → review fixture → compile → existing Knowledge Pack validator → canvas with zero LLM calls.

## P2 — First systematizer

- [ ] Define provider-neutral `Systematizer` interface.
- [ ] Implement one model adapter only.
- [ ] Produce draft contract output, never canonical pack directly.
- [ ] Require evidence/source locators for machine-generated proposals.
- [ ] Persist run/config identity for reproducibility.
- [ ] Run benchmark #001 without manual pre-editing.

**DoD:** transformer produces valid draft or fails explicitly; no hidden repair step.

## P3 — Human review experience

- [ ] Show proposal groups: node additions, relations, merges, conflicts.
- [ ] Display `extracted` vs `inferred` clearly.
- [ ] Show source/evidence for every machine proposal.
- [ ] Support accept/edit/reject per proposal and batch selection.
- [ ] Record review start/completion timestamps.
- [ ] Export review decisions for evaluator.

**DoD:** a reviewer can understand why a proposal exists and correct it before canonicalization.

## P4 — Evaluation runner

## P5 — Benchmark diversity

Only after benchmark #001 produces useful evidence:

- [ ] Case #002: non-agentic product/research corpus.
- [ ] Case #003: decision/problem analysis with competing viewpoints.
- [ ] Case #004: learning/curriculum structure.

**DoD:** product thesis is not inferred from one domain-shaped benchmark.

## Explicitly deferred

Do not add these before v0.4 transformation quality is demonstrated:

- cloud accounts/auth;
- multi-user/tenant storage;
- Gmail/Drive/Notion/Slack connectors;
- continuous sync;
- vector database;
- organization RBAC;
- autonomous graph mutation;
- generalized workflow automation;
- additional visualization polish unrelated to evaluation.

## Decision checkpoints

### Checkpoint A — pipeline validity

Can a deterministic hand-authored draft compile safely into an existing Knowledge Pack?

If no: fix the contract/compiler before AI.

### Checkpoint B — benchmark quality

Can the first model run pass the automated benchmark quality envelope?

If no: inspect failure categories before changing UI.

### Checkpoint C — human correction

Does a knowledgeable reviewer correct ≤ 30% of proposals on representative cases?

If no: systematization quality is not yet sufficient.

### Checkpoint D — TTSU

Does the system-assisted workflow materially beat measured manual reconstruction?

If no: revisit product value, even if graph quality appears good.

### Checkpoint E — generalization

Do multiple distinct benchmark domains retain useful quality?

If no: narrow the wedge or revise the architecture before claiming “systematize anything.”
