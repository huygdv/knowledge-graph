# v0.4 Implementation Backlog

This backlog is subordinate to ADR-003 and `V0.4_SYSTEMATIZATION_EXPERIMENT.md`.

The order is deliberate: measurement infrastructure before transformer sophistication.

## Current checkpoint

**P1 is complete. P2a provider-neutral Systematizer interface is verified. The next evidence-producing step is P2b: one real model adapter + benchmark #001 run.**

Verified foundation so far:

- deterministic core tests: 8/8 passed;
- benchmark #001 gold evaluator remains automated-pass;
- Markdown SourceAdapter normalizes 7 stable fragments;
- 29 reviewed proposals compile to 13 nodes + 16 edges;
- provenance sidecar retains 29 accepted proposal records + 7 source records;
- compiled Knowledge Pack passes Python validation and browser `KGWorkspace.validatePack()`;
- Chromium imports the generated pack and renders benchmark nodes on the existing canvas;
- public Systematizer process contract accepts normalized source and returns only Draft Contract v0.1;
- Systematizer runner records stable run identity, configuration hash, duration and validation result;
- fixture adapter passes request/response identity checks and the benchmark evaluator;
- existing Deep Dive / Knowledge Pack / mentorship browser regressions remain green.

The fixture adapter is a protocol self-test only. It is **not model performance** and must not be used to claim systematization quality.

One non-blocking metadata warning remains intentionally visible: benchmark source #6 uses a shortened human-friendly title while its stable source ID and locator match the normalized fragment. Identity is enforced by source ID + locator, and by content hash when the draft supplies one.

## Decision checkpoints

### Checkpoint A — pipeline validity ✅

Can a deterministic hand-authored draft compile safely into an existing Knowledge Pack?

**Yes. Verified by P1 CI + browser smoke.**

### Checkpoint B — benchmark quality ← NEXT

Can the first **real model run** pass the automated benchmark quality envelope?

Fixture/gold runs do not answer this question.

If no: inspect failure categories before changing UI.

### Checkpoint C — human correction

Does a knowledgeable reviewer correct ≤ 30% of proposals on representative cases?

If no: systematization quality is not yet sufficient.

### Checkpoint D — TTSU

Does the system-assisted workflow materially beat measured manual reconstruction?

If no: revisit product value, even if graph quality appears good.

### Checkpoint E — generalization

Do multiple distinct benchmark domains retain useful quality?

If no: narrow the wedge or revise the architecture before claiming “systematize anything.”
