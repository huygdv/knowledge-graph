# v0.4 Systematization Experiment

- **Status:** Active experiment
- **Parent decision:** ADR-003
- **Goal:** Test whether fragmented information can be transformed into a useful, trustworthy, editable knowledge model with materially less human effort than manual reconstruction.

## Hypothesis

Given a representative corpus of fragmented AI conversations or research notes, a systematization pipeline can produce a reviewable draft knowledge model that:

1. captures the important concepts and relationships;
2. preserves provenance for machine-generated structure;
3. avoids structural invalidity and obvious duplication;
4. requires less than roughly 20–30% structural correction by a knowledgeable reviewer; and
5. reduces **Time to Structured Understanding (TTSU)** versus manual synthesis.

Generating a visually plausible graph is not sufficient evidence.

## Experimental unit

One run has exactly one source corpus and produces one reviewable draft.

```text
source corpus
    ↓
normalization
    ↓
systematizer
    ↓
draft contract
    ↓
deterministic validation + evaluation
    ↓
human review
    ↓
accepted Knowledge Pack
    ↓
existing canvas / Focus Realm
```

v0.4 starts with one input adapter only: pasted Markdown or exported AI-conversation text.

## Variables

### Independent variables

- transformer implementation / prompt / model;
- corpus;
- optional systematization strategy.

### Controlled variables

- draft contract version;
- Knowledge Pack schema version;
- benchmark expectations;
- evaluator implementation;
- review rubric.

### Dependent metrics

- contract/schema validity;
- required-topic recall;
- required-relation recall;
- provenance coverage;
- origin-label accuracy (`extracted` vs `inferred`);
- duplicate concept rate;
- human correction rate;
- accepted-without-rewrite rate;
- TTSU;
- reviewer usefulness/trust verdict.

## Run protocol

1. Freeze the benchmark input before a run.
2. Record transformer identity/configuration and run start time.
3. Produce `draft.json` conforming to `SYSTEMATIZATION_DRAFT_CONTRACT.md`.
4. Run the deterministic evaluator before human review.
5. Reject runs with invalid structure; do not repair them invisibly in the UI.
6. Review every proposal as `accept`, `edit`, or `reject`.
7. Record review completion time and reviewer notes.
8. Compile only accepted/edited proposals into a Knowledge Pack.
9. Render the result in the existing application.
10. Record whether the resulting overview is useful without reopening most original fragments.

## Success gates

A run is **structurally valid** only when:

- contract validation passes;
- all node/edge identifiers are unique;
- relation kinds and node kinds are supported;
- there are zero dangling relation endpoints;
- generated hierarchy has zero cycles after compilation.

A benchmark run is **quality-pass** when its case-specific thresholds pass. The initial target envelope is:

| Metric | Initial target |
|---|---:|
| Contract/schema validity | 100% |
| Required-topic recall | ≥ 85% |
| Required-relation recall | ≥ 75% |
| Provenance coverage | ≥ 90% |
| Origin-label accuracy | ≥ 85% |
| Duplicate concept rate | ≤ 10% |
| Human correction rate | ≤ 30% |
| Accepted without rewrite | ≥ 70% |

TTSU must also be materially better than the measured manual baseline for the same corpus. No synthetic baseline is allowed; it must be measured.

## Human review verdict

After metrics, the reviewer answers three binary questions:

1. Can I recover the major mental model without reopening most source fragments?
2. Can I understand why important generated structure exists by following provenance?
3. Would I continue from this structured model rather than discard it and rewrite manually?

A run cannot be considered a product success if deterministic metrics pass but the reviewer answers `no` to two or more questions.

## Falsification

Pause feature expansion and revisit ADR-003 if several representative cases repeatedly show any of the following:

- human correction > 30% despite prompt/model tuning;
- relation recall or precision remains too low to trust;
- important proposals lack traceable provenance;
- TTSU is not meaningfully lower than manual synthesis;
- users prefer a normal summary because the structure adds little value.

## Explicit non-goals for v0.4

- connectors to Gmail, Notion, Drive, Slack, or browser history;
- autonomous canonical mutation;
- multi-user/cloud sync;
- vector database infrastructure;
- production model routing;
- collaboration/RBAC;
- broad file parsing;
- polishing additional canvas projections unless required to evaluate the experiment.

## Deliverables

- systematization draft contract;
- deterministic evaluation rubric;
- benchmark harness and case format;
- benchmark case #001 from real prior agent-harness research notes;
- executable evaluator;
- implementation backlog for transformer → review → compiler.

## Decision after the experiment

The outcome is one of:

- **Proceed:** evidence supports building the proprietary systematization layer.
- **Iterate:** value exists but quality or TTSU misses a defined threshold; change the transformation strategy, not the visualization.
- **Pivot/stop:** structured modeling does not add enough value over ordinary synthesis for the tested wedge.
